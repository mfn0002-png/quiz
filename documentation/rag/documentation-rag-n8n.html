01
Théorie Fondamentale du RAG (Retrieval-Augmented Generation)
Pourquoi et comment transformer un LLM généraliste en expert de vos documents

Les modèles de langage (LLM) comme Google Gemini possèdent d'immenses connaissances générales, mais souffrent de trois limites critiques en environnement d'entreprise ou dans un domaine spécialisé :

🧠
Hallucinations
Face à une question pointue dont il n'a pas la mémoire exacte, le LLM invente une réponse plausible mais fausse.
📅
Date de Coupure (Cut-off)
Le modèle ne connaît ni vos documents internes récents, ni les derniers textes canoniques ajoutés à votre base.
📚
Coût du Contexte Illimité
Injecter un PDF entier de 500 pages à chaque prompt coûte cher, sature la latence et noie l'attention du modèle.
💡 La Solution RAG (Recherche Augmentée par Génération)
Le principe est simple mais puissant : Ne pas demander au modèle de retenir l'information par cœur, mais lui fournir comme un "examen à livre ouvert" les 3 à 5 paragraphes exacts pertinents au moment où la question est posée.

03
Parsing & Chunking Récursif en pur Node.js
L'art de découper le texte sans casser la cohérence des phrases ni le contexte

Découper par bête nombre de caractères est une erreur courante qui coupe des phrases en deux. Le Recursive Text Splitter respecte la hiérarchie naturelle du langage : paragraphes (\n\n), puis lignes (\n), puis phrases (. ), puis mots.

recursiveChunker.js
/** * Découpeur récursif de texte avec chevauchement (Overlap) * @param {string} text - Le texte brut à découper * @param {number} chunkSize - Taille maximale d'un chunk (ex: 800 caractères) * @param {number} chunkOverlap - Chevauchement pour conserver le contexte (ex: 150 caractères) */ export function recursiveSplitText(text, chunkSize = 800, chunkOverlap = 150) { if (text.length <= chunkSize) return [text.trim()]; const separators = ["\n\n", "\n", ". ", "? ", "! ", " ", ""]; function splitHelper(currentText, sepIndex) { if (currentText.length <= chunkSize) return [currentText.trim()]; if (sepIndex >= separators.length) { // Fallback découpage par index si aucun séparateur ne suffit const chunks = []; for (let i = 0; i < currentText.length; i += (chunkSize - chunkOverlap)) { chunks.push(currentText.slice(i, i + chunkSize)); } return chunks; } const sep = separators[sepIndex]; const parts = sep ? currentText.split(sep) : [currentText]; const result = []; let accumulator = ""; for (const part of parts) { const candidate = accumulator ? accumulator + sep + part : part; if (candidate.length <= chunkSize) { accumulator = candidate; } else { if (accumulator) { result.push(accumulator.trim()); // Gestion de l'overlap const overlapStart = Math.max(0, accumulator.length - chunkOverlap); accumulator = accumulator.slice(overlapStart) + sep + part; } else { // La partie seule dépasse la taille, on descend au séparateur suivant result.push(...splitHelper(part, sepIndex + 1)); accumulator = ""; } } } if (accumulator.trim()) result.push(accumulator.trim()); return result; } return splitHelper(text, 0).filter(c => c.length > 40); }
📌 Pourquoi l'Overlap est capital ?
Si une phrase clé comme "Le taux de la Zakat est fixé à 2.5% à condition que le bien dépasse le seuil du Nisab" est coupée pile entre "2.5%" et "Nisab", le modèle perdra la condition juridique. Le chevauchement de 150 caractères garantit que le contexte ne sera jamais tronqué.

Vectorisation avec Google Gemini (text-embedding-004)
Génération des représentations sémantiques 768-D avec le SDK officiel Node.js

Nous utilisons le modèle officiel models/text-embedding-004 via @google/generative-ai. Il différencie automatiquement le type de tâche grâce aux paramètres TaskType : RETRIEVAL_DOCUMENT pour l'indexation, et RETRIEVAL_QUERY pour la question utilisateur.

geminiEmbeddings.js
import { GoogleGenerativeAI, TaskType } from '@google/generative-ai'; const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY); const embeddingModel = genAI.getGenerativeModel({ model: 'text-embedding-004' }); /** * Calcule l'embedding pour un texte de document (Indexation) */ export async function embedDocumentChunk(text) { const response = await embeddingModel.embedContent({ content: { parts: [{ text }] }, taskType: TaskType.RETRIEVAL_DOCUMENT }); return response.embedding.values; // Array de 768 floats } /** * Calcule l'embedding pour la question de l'utilisateur (Recherche) */ export async function embedUserQuery(query) { const response = await embeddingModel.embedContent({ content: { parts: [{ text: query }] }, taskType: TaskType.RETRIEVAL_QUERY }); return response.embedding.values; }

Stockage Vectoriel : Supabase (PgVector) & Local In-Memory
Comment stocker, indexer et requêter des millions de dimensions en Node.js

Pour tester immédiatement ou pour un document de référence de taille modérée (quelques centaines de pages), un Vector Store local en Node.js avec sauvegarde JSON et calcul cosinus en mémoire est ultra rapide (< 2ms) et ne nécessite aucun compte cloud !

localVectorStore.js
import fs from 'node:fs/promises'; export class LocalVectorStore { constructor(filePath = './knowledge_store.json') { this.filePath = filePath; this.documents = []; // [{ id, content, metadata, embedding }] } async load() { try { const data = await fs.readFile(this.filePath, 'utf-8'); this.documents = JSON.parse(data); } catch { this.documents = []; } } async save() { await fs.writeFile(this.filePath, JSON.stringify(this.documents, null, 2)); } addDocuments(docs) { this.documents.push(...docs); } }

Pour un stockage managé en production à grande échelle (millions de documents), Supabase (PostgreSQL avec l'extension pgvector) est la solution de référence. Voici le schéma SQL officiel et son client Node.js complet :

supabase_schema.sql
-- 1. Activer l'extension vectorielle CREATE EXTENSION IF NOT EXISTS vector; -- 2. Table documents (Adapter la taille au modèle : 768 pour text-embedding-004, 3072 pour gemini-embedding-001) CREATE TABLE IF NOT EXISTS documents ( id BIGSERIAL PRIMARY KEY, content TEXT, metadata JSONB, embedding VECTOR(768) ); -- 3. Fonction RPC de recherche par similarité cosinus CREATE OR REPLACE FUNCTION match_documents ( query_embedding VECTOR(768), match_count INT DEFAULT 5, filter JSONB DEFAULT '{}' ) RETURNS TABLE ( id BIGINT, content TEXT, metadata JSONB, similarity FLOAT ) LANGUAGE plpgsql AS $$ BEGIN RETURN QUERY SELECT d.id, d.content, d.metadata, 1 - (d.embedding <=> query_embedding) AS similarity FROM documents d WHERE filter = '{}' OR d.metadata @> filter ORDER BY d.embedding <=> query_embedding LIMIT match_count; END; $$;

Client Node.js Supabase (Insertion & Recherche Vectorielle) :

supabaseVectorStore.js
import { createClient } from '@supabase/supabase-js'; const supabase = createClient( process.env.SUPABASE_URL, process.env.SUPABASE_SERVICE_ROLE_KEY ); /** * 1. Insertion de chunks vectorisés dans Supabase */ export async function insertChunksToSupabase(chunksWithEmbeddings) { const rows = chunksWithEmbeddings.map(c => ({ content: c.content, metadata: c.metadata, embedding: c.embedding // Array de 768 (ou 3072) floats })); const { data, error } = await supabase .from('documents') .insert(rows); if (error) throw new Error(`Erreur insertion: ${error.message}`); return data; } /** * 2. Recherche par Similarité Cosinus via RPC match_documents */ export async function searchSimilarInSupabase(queryEmbedding, matchCount = 3) { const { data, error } = await supabase.rpc('match_documents', { query_embedding: queryEmbedding, match_count: matchCount, filter: {} }); if (error) throw new Error(`Erreur recherche RPC: ${error.message}`); return data; // [{ id, content, metadata, similarity }, ...] }

Algorithme de Retrieval : Similarité Cosinus en Pur JavaScript
Calcul géométrique de l'angle entre la question et les extraits documentaires

La similarité cosinus mesure le cosinus de l'angle entre deux vecteurs $A$ et $B$ dans un espace à 768 dimensions : $$\text{Similarité} = \frac{A \cdot B}{\|A\| \times \|B\|}$$ Plus le score est proche de 1.0, plus les textes sont sémantiquement identiques.

similaritySearch.js
/** * Calcule la similarité cosinus entre 2 vecteurs en pur JS */ export function cosineSimilarity(vecA, vecB) { let dotProduct = 0; let normA = 0; let normB = 0; for (let i = 0; i < vecA.length; i++) { dotProduct += vecA[i] * vecB[i]; normA += vecA[i] * vecA[i]; normB += vecB[i] * vecB[i]; } if (normA === 0 || normB === 0) return 0; return dotProduct / (Math.sqrt(normA) * Math.sqrt(normB)); } /** * Recherche les K documents les plus proches de la requête */ export function searchTopK(queryEmbedding, documents, topK = 4, minScore = 0.60) { const scored = documents.map(doc => ({ ...doc, similarity: cosineSimilarity(queryEmbedding, doc.embedding) })); // Trie par pertinence décroissante et applique le filtre de score minimum return scored .filter(doc => doc.similarity >= minScore) .sort((a, b) => b.similarity - a.similarity) .slice(0, topK); }

Prompt Augmenté & Inférence : Zéro Hallucination
Forcer le modèle à citer obligatoirement ses sources et refuser de spéculer

Pour garantir une fiabilité maximale, le prompt est scindé en deux : un systemInstruction impératif et un prompt utilisateur contenant le contexte injecté.

ragSynthesizer.js
import { GoogleGenerativeAI } from '@google/generative-ai'; const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY); export async function generateRagAnswer(userQuestion, matchedChunks) { // 1. Formatage des extraits documentaires avec leurs métadonnées const contextText = matchedChunks.map((chunk, index) => { const { source, page } = chunk.metadata || {}; return `[EXTRAIT ${index + 1} | Source: ${source || 'Doc'} | Page: ${page || 'N/A'}] ${chunk.content}`; }).join("\n\n---\n\n"); // 2. Directives strictes anti-hallucination const systemInstruction = `Tu es un assistant de référence hautement rigoureux. Tu dois répondre à la question de l'utilisateur EN TE BASANT STRICTEMENT et UNIQUEMENT sur les extraits fournis. RÈGLES IMPÉRATIVES : 1. ZÉRO HALLUCINATION : Si l'information ne se trouve pas explicitement dans les extraits, réponds clairement : "D'après les documents fournis, cette information n'est pas précisée." 2. Ne fais aucune supposition ou extrapolation non écrite. 3. À la fin de chaque affirmation, cite la source et la page exacte entre crochets (ex: [Source: Rules.pdf, Page 4]). 4. Garde un ton professionnel, bienveillant et structuré.`; const model = genAI.getGenerativeModel({ model: 'gemini-1.5-flash', systemInstruction }); const prompt = `DOCUMENTS DE RÉFÉRENCE : ${contextText} QUESTION DE L'UTILISATEUR : ${userQuestion}`; const result = await model.generateContent(prompt); return result.response.text(); }

Pipeline Complet Node.js Clé en Main (ragPipeline.js)
Un script unique, autonome et modulaire prêt pour votre backend NoorQuiz

Voici le fichier complet qui orchestre l'ingestion, le stockage vectoriel local et le requêtage. Vous pouvez le placer directement dans votre dossier backend/src/services/ragPipeline.js :

backend/src/services/ragPipeline.js
/** * ragPipeline.js — Pipeline RAG Vectoriel Complet en Pur Node.js * Compatible Google Gemini (text-embedding-004 + gemini-1.5-flash) */ import fs from 'node:fs/promises'; import path from 'node:path'; import { GoogleGenerativeAI, TaskType } from '@google/generative-ai'; import dotenv from 'dotenv'; dotenv.config(); const genAI = new GoogleGenerativeAI(process.env.GEMINI_API_KEY); const embedModel = genAI.getGenerativeModel({ model: 'text-embedding-004' }); const STORE_FILE = path.resolve('./knowledge_store.json'); // 1. CHUNKER RÉCURSIF export function chunkText(text, chunkSize = 800, overlap = 150) { const seps = ["\n\n", "\n", ". ", " "]; const chunks = []; let cur = ""; for (const p of text.split("\n\n")) { if ((cur + p).length <= chunkSize) { cur += (cur ? "\n\n" : "") + p; } else { if (cur) chunks.push(cur.trim()); cur = p; } } if (cur.trim()) chunks.push(cur.trim()); return chunks; } // 2. CALCUL EMBEDDING export async function getEmbedding(text, isQuery = false) { const res = await embedModel.embedContent({ content: { parts: [{ text }] }, taskType: isQuery ? TaskType.RETRIEVAL_QUERY : TaskType.RETRIEVAL_DOCUMENT }); return res.embedding.values; } // 3. CALCUL SIMILARITÉ COSINUS export function cosine(a, b) { let dot = 0, nA = 0, nB = 0; for (let i = 0; i < a.length; i++) { dot += a[i] * b[i]; nA += a[i] * a[i]; nB += b[i] * b[i]; } return dot / (Math.sqrt(nA) * Math.sqrt(nB)); } // 4. INGESTION DU DOCUMENT export async function ingestDocument(filePath) { console.log(`📄 Lecture du fichier : ${filePath}`); const content = await fs.readFile(filePath, 'utf-8'); const rawChunks = chunkText(content, 800, 150); console.log(`✂️ ${rawChunks.length} chunks générés. Calcul des vecteurs...`); const store = []; for (let i = 0; i < rawChunks.length; i++) { const emb = await getEmbedding(rawChunks[i], false); store.push({ id: i + 1, content: rawChunks[i], metadata: { source: path.basename(filePath), chunkIndex: i }, embedding: emb }); // Pause de courtoisie pour le quota API await new Promise(r => setTimeout(r, 150)); } await fs.writeFile(STORE_FILE, JSON.stringify(store, null, 2)); console.log(`💾 Base sauvegardée dans ${STORE_FILE} !`); } // 5. QUESTION / RÉPONSE AVEC RAG export async function askRag(question, topK = 3) { const rawStore = await fs.readFile(STORE_FILE, 'utf-8'); const store = JSON.parse(rawStore); const qEmb = await getEmbedding(question, true); const scored = store.map(d => ({ ...d, sim: cosine(qEmb, d.embedding) })) .sort((a, b) => b.sim - a.sim) .slice(0, topK); const context = scored.map(s => `[Source: ${s.metadata.source}] ${s.content}`).join("\n\n"); const chatModel = genAI.getGenerativeModel({ model: 'gemini-1.5-flash', systemInstruction: "Réponds UNIQUEMENT d'après le contexte. Cite la source. Zéro hallucination." }); const res = await chatModel.generateContent(`CONTEXTE:\n${context}\n\nQUESTION:\n${question}`); return res.response.text(); }

Synergie d'Architecture : RAG vs MCP dans NoorQuiz
Comment ces deux technologies se complètent parfaitement dans votre plateforme

Il ne faut pas opposer RAG et MCP (Model Context Protocol). Dans une application moderne d'Agent IA, ils ont des rôles distincts et complémentaires :

Critère RAG Vectoriel (Embeddings) MCP (Outils / Actions Dynamiques)
Nature de la donnée Corpus textuel dense, livres, cours, PDF de jurisprudence. Données dynamiques en temps réel, calculs et bases SQL.
Méthode d'accès Indexation sémantique (similarité cosinus). Appel de fonctions typées (Tool Calling JSON Schema).
Cas d'usage dans NoorQuiz Recherche dans la documentation officielle et les règles de foi. Calcul de la Zakat, horaires de prière locaux, calendrier hégirien du jour.
Temps de réponse Ultra rapide (< 20ms pour la recherche vectorielle). Dépend de la latence de l'API externe appelée.
🎯 L'Architecture Idéale de l'Agent NoorQuiz :
L'agent intelligent utilise le RAG Vectoriel pour comprendre la théorie religieuse et les règles doctrinales, et utilise ses Outils MCP dès qu'il a besoin d'exécuter un calcul précis (Zakat) ou de récupérer des horaires dynamiques selon la géolocalisation !

De la Recherche Documentaire à l'Agent Autonome : Le RAG comme Outil Déterministe
Séparation des responsabilités : découpler l'indexation du savoir et l'orchestration cognitive

Dans une architecture d'IA moderne, la performance ne provient pas de l'accumulation de modèles génératifs en cascade, mais de la spécialisation stricte de chaque composant technique.

Si un pipeline RAG classique se limite traditionnellement à un schéma rigide « Question ➔ Recherche ➔ Réponse figée », l'intégration agentique de NoorQuiz élève le RAG au rang de sens spécialisé (un outil d'extraction documentaire) piloté par un Agent central.

Ce découplage structurel répond à un enjeu clé de conception : comment allier la rigueur factuelle du RAG et l'intelligence adaptative de l'Agent sans redondance ? La réponse repose sur la séparation claire des rôles : le RAG excelle dans le filtrage mathématique et l'extraction de preuves (sans jamais générer de texte), tandis que l'Agent gouverne le raisonnement, la mémoire de la session et la prise de décision.

✂️
1. Chunking : Zéro LLM
Le découpage du texte est 100% algorithmique en JavaScript (expressions régulières sur la ponctuation). Aucun modèle d'IA n'est sollicité.
📐
2. Embeddings : Pas de génération
Le modèle d'embedding (text-embedding-004) ne génère aucun texte. C'est une projection mathématique pure qui convertit des mots en 768 coordonnées.
🔍
3. Retrieval : Produit Scalaire
La recherche des passages est un calcul géométrique de similarité cosinus. C'est instantané, déterministe et sans intelligence artificielle générative.
🧠
4. Un Seul et Unique LLM
L'Agent est l'unique cerveau conversationnel. Le RAG lui transmet uniquement des extraits bruts. L'Agent lit ces extraits et rédige la réponse finale.
❌

Approche Naïve : Pipeline RAG Isolé (2 LLMs)

Le RAG génère une réponse fermée avec son propre LLM, puis l'Agent réinjecte cette réponse dans un second LLM pour la reformuler.

Utilisateur ➔ LLM 1 (Agent)
  ➔ Requête RAG
    ➔ LLM 2 (RAG Génératif) : Rédige réponse
  ➔ Retour texte à l'Agent
  ➔ LLM 1 (Agent) : Reformule la réponse
⚠️ Bilan : 2 LLMs génératifs, Coût x2, Latence x2, Duplication !
✅

Notre Approche : RAG comme Outil (1 Seul LLM)

Le RAG est un simple indexeur vectoriel sans génération (recherche pure). L'Agent NoorQuiz est l'unique cerveau de synthèse.

Utilisateur ➔ LLM Unique (Agent NoorQuiz)
  ➔ Appel Outil search_knowledge_base
    ➔ Calcul similarité cosinus (0 LLM)
    ➔ Renvoie 3 extraits bruts (0 LLM)
  ➔ LLM Unique : Synthèse certifiée finale
✨ Bilan : 1 Seul LLM, 0 Duplication, Vitesse & Précision maximales !

Comparatif Approfondi des Deux Approches :

Critère d'Évaluation ❌ Approche Naïve : Pipeline RAG Isolé ✅ Notre Approche : RAG comme Outil de l'Agent
Nombre de LLMs actifs 2 LLMs (1 dans le RAG qui formule une réponse figée + 1 Agent qui la reformule). 1 Seul LLM (L'Agent utilise le RAG comme un simple moteur de recherche documentaire).
Coût et Latence API Doublés (deux générations complètes de tokens). Optimisés (une seule génération finale de texte).
Gestion de l'Historique Le RAG isolé oublie la conversation précédente. L'Agent intègre la mémoire Redis et le contexte global du joueur.
Pertinence de l'Appel Le RAG s'exécute bêtement même pour un simple "Bonjour" ou "Merci". L'Agent décide intelligemment si et quand interroger la base documentaire.
Actions Multiples Incapable de proposer un quiz ou de calculer une zakat après la réponse. L'Agent peut chaîner RAG + Calcul Zakat + Proposition de Quiz interactif.
💡 La Métaphore de l'Avocat et de sa Bibliothèque :
Considérez votre Agent comme un avocat expérimenté et le RAG comme sa bibliothèque juridique. L'avocat ne récite pas tout de mémoire (sinon il risque d'halluciner). Quand vous lui posez une question pointue sur la Zakat, il se lève, consulte précisément les 3 pages de référence dans sa bibliothèque (RAG), puis revient vers vous pour vous expliquer la règle avec bienveillance et clarté.
