🔌 Qu'est-ce que le Model Context Protocol (MCP) ?
Le standard ouvert qui connecte les LLMs aux outils et données du monde réel
💡
Définition officielle (Anthropic, 2024) MCP est un protocole ouvert standardisé qui définit comment une application hôte (l'agent) peut découvrir et appeler des outils, accéder à des ressources et utiliser des prompts fournis par un serveur MCP — sans rien coder en dur.
🧩
Protocole standardisé
Comme HTTP pour le web, MCP définit un contrat unique entre agents et outils. Un serveur MCP peut se connecter à n'importe quel client compatible (Gemini, Claude, GPT…).
🔍
Découverte dynamique
L'agent demande au serveur la liste des outils disponibles (tools/list) au démarrage. Le LLM peut alors choisir intelligemment quel outil appeler.
🔒
Isolation & sécurité
Le serveur MCP tourne en processus séparé. Le LLM ne touche jamais directement les APIs — il passe toujours par le serveur, ce qui limite la surface d'attaque.
🌐
Multi-transport
MCP supporte stdio (local), HTTP+SSE (réseau) et WebSocket. On peut déployer le serveur localement ou en cloud selon les besoins.
🎯
Analogie clé MCP est au LLM ce que le driver JDBC est à une application Java : une couche d'abstraction standardisée qui permet de se connecter à n'importe quelle source sans changer le code applicatif.

1
Initialisation — Poignée de main (Handshake)
Au démarrage, le client envoie un message initialize au serveur. Le serveur répond avec sa version, ses capacités et la liste complète des outils. Cette découverte dynamique est essentielle : le LLM apprend ce qu'il peut faire sans que le code soit modifié.
2
Injection des outils dans le contexte Gemini
Le client injecte les définitions JSON des outils MCP dans le contexte envoyé à Gemini (via tools: [...]). Chaque outil a un name, une description en langage naturel et un inputSchema JSON Schema.
3
Raisonnement et sélection d'outil (Gemini)
Gemini analyse la question et choisit de manière autonome quel outil appeler et avec quels arguments. Il renvoie un function_call — pas encore une réponse texte. C'est le cœur du comportement agentique.
4
Exécution via le Serveur MCP
Le client reçoit le function_call et appelle le serveur MCP via tools/call en JSON-RPC 2.0. Le serveur route vers le bon handler, exécute la logique métier (appel API, requête BDD…) et retourne le résultat structuré.
5
Synthèse de la réponse finale
Le client renvoie le résultat de l'outil à Gemini en tant que function_response. Gemini synthétise alors une réponse en langage naturel enrichie des données réelles.
6
Réponse à l'utilisateur
L'agent retourne la réponse finale, enrichie de données authentiques, à l'interface. Tout ce cycle se déroule en quelques centaines de millisecondes.

🔧 Les 3 primitives MCP : Outils, Ressources & Prompts
Ce qu'un serveur MCP peut exposer à l'agent

Les Tools sont des fonctions exécutables côté serveur. L'agent peut les invoquer pour faire des choses — appels API, calculs, écriture en base, etc.

search_duas
Recherche des invocations dans Hisn al-Muslim par thème. Retourne texte arabe, phonétique et traduction.
GETlecture seule
search_quran
Recherche de versets par mot-clé, sourate ou thème. Retourne verset, référence et tafsir simplifié.
GETlecture seule
calculate_zakat
Calcule la Zakat selon les données financières fournies. Retourne le montant et la méthode de calcul.
COMPUTEavec effet
prayer_times
Horaires de prière pour une localisation et une date. Retourne Fajr, Dhuhr, Asr, Maghrib, Isha.
GETtemps réel

Les Resources sont des données accessibles en lecture — fichiers, corpus, entrées de base — que l'agent peut inclure dans son contexte.

📄
Différence clé : Resource vs Tool Les Resources sont passives (l'agent lit). Les Tools sont actifs (l'agent agit). Dans notre architecture, les corpus Coran et Hadiths sont exposés comme Resources pour le Quiz Agent, tandis que search_quran est un Tool pour l'Assistant Agent. 
// Déclaration d'une Resource dans islamicMcpServer.js
server.resource(
  "quran-corpus",
  "islamic://quran/full",
  async (uri) => ({
    contents: [{
      uri: uri.href,
      mimeType: "application/json",
      text: await loadQuranCorpus()
    }]
  })
);

Les Prompts MCP sont des templates réutilisables exposés par le serveur. L'agent peut les appeler pour obtenir un prompt pré-construit adapté à une tâche.

💬
Cas d'usage dans notre projet Le Quiz Agent appelle le prompt MCP generate_quiz_prompt pour obtenir un template déjà formaté avec les instructions de sourcing islamique — évitant la duplication dans plusieurs agents. 
// Prompt MCP template pour la génération de quiz
server.prompt(
  "generate_quiz_prompt",
  { theme: z.string(), difficulty: z.string() },
  ({ theme, difficulty }) => ({
    messages: [{
      role: "user",
      content: {
        type: "text",
        text: `Génère 5 questions sur ${theme}
(niveau ${difficulty}) basées uniquement
sur le Coran et les hadiths authentiques.`
      }
    }]
  })
);

Chaque outil MCP est décrit par un JSON Schema. C'est ce schéma que Gemini reçoit pour savoir comment appeler l'outil correctement.

// Définition complète d'un outil MCP (islamicMcpServer.js)
server.tool(
  "search_duas",
  "Recherche des invocations authentiques dans Hisn al-Muslim",
  {
    topic: z.string().describe("Thème en français ou arabe (ex: voyage, repas, sommeil)"),
    limit: z.number().optional().describe("Nombre max de résultats (défaut: 3)"),
    language: z.enum(["fr", "ar", "both"]).optional()
  },
  async ({ topic, limit = 3, language = "both" }) => {
    const results = await duasService.search(topic, limit, language);
    return {
      content: [{ type: "text", text: JSON.stringify(results) }]
    };
  }
);

🚌 Les Transports MCP — Comment client et serveur communiquent
MCP est agnostique au transport : stdio, HTTP+SSE ou WebSocket
Transport Description Cas d'usage Notre choix
stdio Le serveur tourne en sous-processus local. Client et serveur échangent via les flux standards (stdin / stdout). Chaque message JSON-RPC est délimité par un saut de ligne (\n). Développement local, outils CLI, extensions desktop, environnements sans réseau ✅ Dev local
HTTP + SSE Le serveur expose un endpoint HTTP. Les réponses utilisent Server-Sent Events (SSE) pour le streaming temps réel. Production, microservices, déploiement cloud, multi-clients ✅ Production
WebSocket Connexion bidirectionnelle persistante. Latence minimale pour les échanges haute fréquence. Agents temps réel, streaming long, connexions durables Futur
💡
C'est quoi stdio (Standard Input / Output) ? stdio désigne les mécanismes d'entrées-sorties standard du système d'exploitation permettant de lire des données et d'en afficher (popularisés par la bibliothèque standard C <stdio.h>).
Dans le cadre de MCP et de la communication inter-processus (IPC) :
  • stdin (entrée standard) : le client envoie ses requêtes JSON-RPC au serveur MCP sous forme de texte.
  • stdout (sortie standard) : le serveur MCP renvoie ses réponses JSON-RPC au client.
  • stderr (erreur standard) : utilisé séparément pour les logs et le debug sans corrompre le flux de données.
Ce mode est extrêmement rapide, sécurisé (aucun port réseau exposé) et idéal pour exécuter des serveurs MCP en local.
🔄
Protocole sous-jacent : JSON-RPC 2.0 Tous les messages MCP sont des objets JSON-RPC 2.0 — format léger, structuré, avec gestion native des erreurs. Chaque requête a un id unique, une method (tools/list, tools/call, resources/read…) et des params. 
// Exemple de message JSON-RPC 2.0 envoyé au serveur MCP
{
  "jsonrpc": "2.0",
  "id": 42,
  "method": "tools/call",
  "params": {
    "name": "search_duas",
    "arguments": {
      "topic": "voyage",
      "limit": 3
    }
  }
}

Pourquoi "Agentic Pur" ? Aucune logique de routage hardcodée. Il n'y a pas de if (message.includes("doua")) callDuaService(). C'est Gemini qui décide, à chaque requête, quel outil est pertinent. L'agent est entièrement piloté par le LLM.

🔀
Différence Quiz Agent vs Assistant Agent Dans le Quiz Agent, le RAG précède Gemini : on collecte d'abord le contexte via MCP, puis on le fournit à Gemini pour la génération. Dans l'Assistant Agent, Gemini décide d'appeler MCP. Les deux patterns sont valides — le choix dépend du besoin de contrôle vs d'autonomie.

⚠️
MCP et RAG sont complémentaires, pas concurrents Dans notre architecture, le Quiz Agent utilise les deux : MCP pour récupérer les données islamiques structurées, et RAG pour assembler le contexte avant de le soumettre à Gemini. C'est le meilleur des deux mondes.
💡
Agent + RAG : Pourquoi ce n'est pas duplicatif ? Le RAG agit comme un simple outil de recherche vectorielle déterministe (0 LLM pour découper, 0 LLM pour chercher les similarités cosinus). L'Agent NoorQuiz reste l'unique cerveau de génération. Il n'y a donc aucun double emploi ni double facturation de tokens ! (Voir le détail complet dans la Section 10 de la documentation RAG).

✨ Architecture 100% Propre :
• MCP : protocole standardisé — l'agent découvre et appelle les outils dynamiquement, sans logique hardcodée.
• Assistant : Gemini décide directement des actions (zéro appel aveugle, zéro regex bricolée).
• Quiz : Le RAG enrichit les thèmes de questions de manière ciblée via les outils MCP.
• MCP Server : Couche universelle, isolée et unique d'accès aux services islamiques.
